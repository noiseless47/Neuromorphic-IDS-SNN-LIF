\chapter{System Design and Methodology}

The proposed system is designed as a modular pipeline that converts network traffic records into circuit-compatible spike waveforms. The design separates data processing, spike encoding, waveform generation, LIF circuit processing and classifier integration. This separation allows the software and hardware parts of the interdisciplinary project to be developed independently while sharing a clearly defined interface.

\section{Design Philosophy}

The central design philosophy is to preserve IDS-relevant information while changing the representation from dense numerical vectors to spike events. In a conventional software pipeline, all features are processed as numbers. In the proposed neuromorphic pipeline, features are first reduced, then encoded as spikes, and then processed by neuron dynamics. This makes the computation more suitable for analog event-driven hardware.

The design must satisfy two competing requirements. First, it must remain faithful to the original IDS dataset so that attack labels and feature meaning are not lost. Second, it must produce a representation that is practical for circuit simulation. PCA and spike encoding are used to balance these requirements.

\section{Non-Functional Requirements}

The non-functional requirements are:
\begin{enumerate}
\item \textbf{Reproducibility}: Scripts must generate the same processed files when run with the same data and parameters.
\item \textbf{Hardware compatibility}: PWL output files must be directly usable in SPICE/Cadence voltage sources.
\item \textbf{Modularity}: Each processing stage must be testable without requiring the entire system.
\item \textbf{Scalability}: The pipeline must allow more samples and more neuron channels to be generated later.
\item \textbf{Traceability}: Generated folders must preserve sample index and class label information.
\end{enumerate}

\section{Data Pipeline Methodology}

The data pipeline follows a fixed sequence:
\begin{enumerate}
\item Load all raw UNSW-NB15 CSV files.
\item Concatenate records into a single dataframe.
\item Generate derived features such as packet rate.
\item Remove IP addresses, timestamps and binary label fields.
\item Clean missing or placeholder values.
\item Encode categorical fields into numerical values.
\item Normalize all features using Min-Max scaling.
\item Apply PCA to reduce the feature count.
\item Normalize PCA outputs again to the 0 to 1 range.
\item Save the processed analog feature dataset.
\end{enumerate}

This methodology ensures that the final file contains only hardware-facing analog features and the corresponding attack category label.

\section{PCA-to-Neuron Mapping}

The number of PCA components is selected based on the target number of physical input neurons. A direct mapping is used:
\begin{equation}
N_{PCA} = N_{input\_neurons}
\end{equation}
For the current design, $N_{PCA}=8$. This means each network sample is represented by eight analog feature values:
\begin{equation}
S_i = [p_1, p_2, p_3, p_4, p_5, p_6, p_7, p_8]
\end{equation}
where each $p_i$ is normalized between 0 and 1. This vector becomes the input to the spike encoder.

\section{Spike Encoding Methodology}

For each normalized PCA value, the encoder generates spike trains. Population coding uses multiple receptive fields per input feature. If $M$ is the number of population neurons per feature, the total number of input spike channels is:
\begin{equation}
N_{channels} = N_{PCA} \times M
\end{equation}
With eight PCA features and four population neurons per feature:
\begin{equation}
N_{channels} = 8 \times 4 = 32
\end{equation}

The spike encoder interfaces directly with the circuit-level LIF neuron model. The following subsections describe how the encoded software waveform is physically translated into membrane integration, threshold detection, and reset behaviour in analog hardware.

\subsection{Power Supply and Bias}
A single $V_{DD}$ supply of $1.2\text{ V}$ (source \texttt{V4}) powers the entire neuron circuit. A secondary precision voltage source (\texttt{V1}) provides the critical comparator reference voltages, with $V_{high} = 500\text{ mV}$ acting as the firing threshold and $V_{low} = 100\text{ mV}$ acting as the reset level. These precise values define the dynamic operating range, the firing threshold, and the hyperpolarisation floor of the physical neuron model.

\subsection{Input Stage and Stimulus Coupling}
A pulse voltage source \texttt{V0}, with $1.2\text{ V}$ amplitude, drives the gate of the primary NMOS transistor (\texttt{nmos1v}). A series resistor \texttt{R2} and the surrounding bias network carefully condition the input signal before it reaches the active device. The NMOS transistor effectively acts as a transconductance amplifier, converting the PWL voltage stimulus generated by the Python pipeline into a controlled charging current delivered to the central membrane node (\texttt{vmembrane}).

\subsection{Leaky Integrator and RC Time Constant Calibration}
The core of the neuromorphic computation occurs at the leaky integrator. The membrane capacitor \texttt{C0} ($20\text{ pF}$) accumulates the injected charge, modeling biological membrane capacitance ($C_m$). The leak path is realized by a resistor \texttt{R0} ($50\text{ M}\Omega$) in parallel with \texttt{C0}, providing passive discharge that reproduces the sub-threshold exponential decay of the membrane potential. 

The calibration of this RC time constant is critical for synchronization with the software PWL pulses. The membrane time constant is defined as:
\begin{equation}
\tau_m = R_0 \times C_0 = 50\text{ M}\Omega \times 20\text{ pF} = 1.0\text{ ms}
\end{equation}
Because the Python spike encoder generates pulses that are exactly $1.0\text{ ms}$ in duration, setting $\tau_m \approx 1.0\text{ ms}$ ensures that the capacitor can charge efficiently and reach the $500\text{ mV}$ firing threshold during a single active input pulse, preventing signal attenuation.

\subsection{Biasing Network}
Two CMOS transistors, \texttt{pmos1v} and \texttt{nmos1x}, form a current-mirror biasing structure that provides the steady-state leakage and integration currents to the membrane. Their drain currents set the precise operating point of the neuron, actively stabilizing the charging and leakage behavior across highly variable simulation environments and temperature corners.

\subsection{Spike Comparator and Threshold Detection}
A three-terminal voltage comparator block (\texttt{I5}) continuously monitors the membrane potential $V_{memb}$, comparing it against the high threshold $V_{th} = 500\text{ mV}$, and the low reference $V_{bn} = 100\text{ mV}$. When $V_{memb}$ exceeds $V_{th}$, the comparator output $V_{comp}$ (\texttt{net025}) transitions sharply high to approximately $1.2\text{ V}$, generating a digital output spike. The comparator output then drives an output resistor \texttt{R5} ($100\text{ k}\Omega$) and a small load capacitor \texttt{C3} ($2\text{ pF}$) for signal shaping.

\subsection{Reset Mechanism and Refractory Period}
When a spike is successfully generated, the comparator output instantly feeds back through resistor \texttt{R4} ($18\text{ k}\Omega$) to the membrane node. This rapidly discharges \texttt{C0} toward the reset voltage of approximately $100\text{ mV}$. This mechanism biologically mimics the after-hyperpolarisation (AHP) behavior and algorithmically sets the necessary refractory interval between consecutive spikes.

\section{PWL File Interface}

The PWL file interface is the most crucial design decision for achieving true interdisciplinary integration. It allows the Information Science software pipeline to export mathematical spike events in a format that the Electronics and Communication Cadence/LTSpice circuit simulator can ingest natively. Each generated `.txt` file contains exactly one spike train, formatted as highly precise time-voltage floating-point pairs.

For example, a population-coded sample generates a highly structured directory:
\begin{verbatim}
sample_0_cat_6/
  V_neuron_0_m_0.txt
  V_neuron_0_m_1.txt
  V_neuron_0_m_2.txt
  ...
  V_neuron_7_m_3.txt
\end{verbatim}
Here, \texttt{V\_neuron\_0} refers to the first PCA-reduced network feature, and \texttt{m\_1} refers to the second Gaussian population receptive field tuned to that specific feature range. This results in exactly 32 stimulus files per network flow.

\section{Spike Feature Extraction Design}

After completion of the transient SPICE simulation, the analog output waveform must be digitally converted back into numerical features. A strictly threshold-based rising-edge detection algorithm is employed on the Python side to parse the exported raw `.csv` reports. This avoids erroneously counting a single wide hardware pulse as multiple distinct events. If the simulated output voltage crosses from low to high ($>0.5\text{ V}$), exactly one spike is tallied. 

The comprehensively extracted features include:
\begin{enumerate}
\item \textbf{Total Spike Count}: The absolute number of threshold crossings per channel.
\item \textbf{First Spike Time}: The latency indicating the strength of the stimulus.
\item \textbf{Mean Inter-Spike Interval (ISI)}: The average temporal distance between consecutive spikes.
\item \textbf{Firing Rate}: The spikes measured per unit time.
\item \textbf{Maximum Membrane Voltage}: Used for debugging attenuation issues.
\end{enumerate}

These precise numerical features bridge the gap between continuous analog neuron responses and the discrete numerical vectors required by the final SVM classifier.

\section{Validation Methodology}

The overall project validation is systematically planned in layered, isolated stages:
\begin{enumerate}
\item \textbf{Software Processing}: Verify processed CSV generation from the raw dataset, ensuring the PCA output is perfectly scaled between 0 and 1.
\item \textbf{Software Encoding}: Verify that generated population spike trains mathematically match the selected Gaussian distributions.
\item \textbf{Interface Generation}: Verify that generated PWL files contain valid, non-flatlined time-voltage floating-point pairs.
\item \textbf{Hardware Stimulation}: Verify that the selected PWL files can successfully drive the Cadence LIF neuron circuit without simulator convergence errors.
\item \textbf{Hardware Output}: Verify that the analog membrane potential integrates properly and the output node generates logic-high spikes.
\item \textbf{Classification}: Verify that the parsed waveforms can successfully train a Support Vector Machine (SVM) to detect intrusions.
\end{enumerate}

This rigidly layered strategy drastically reduces interdisciplinary debugging difficulty.

\section{Risk and Design Mitigation}

Numerous architectural risks are mitigated in this design. PCA inherently discards variance; to mitigate this, the number of components is scientifically aligned with hardware constraints (8 physical inputs mapped to 32 channels) while preserving maximum statistical variance. Furthermore, PWL files with ideal square waves can cause severe SPICE simulator matrix convergence failures; therefore, the Python encoder deliberately injects a 1\% rise/fall duration. 

Crucially, analog LIF circuits are exceptionally sensitive to internal resistance and capacitance parameters. If the RC time constant ($\tau_m$) is too large relative to the software-defined PWL input pulse duration ($1.0\text{ ms}$), the membrane voltage will experience severe attenuation and fail to reach the $500\text{ mV}$ firing threshold. To mitigate this risk, the design enforces precise calibration of \texttt{R0} ($50\text{ M}\Omega$) and \texttt{C0} ($20\text{ pF}$) to achieve $\tau_m \approx 1.0\text{ ms}$, ensuring perfect synchronization between the software inputs and hardware dynamics.

\section{Design Summary}

The proposed system design cleanly connects a massive, high-dimensional IDS dataset to a microscopic neuromorphic circuit interface. The primary scientific contribution of this architecture is the construction of an end-to-end data-to-PWL-to-Circuit pathway. This enables complex abstract network traffic features to be instantiated as physical voltage waveforms that successfully stimulate custom analog LIF neuron circuits. The subsequent chapter explains how this design is robustly implemented within the deployed system modules.
